Implementation proposal — Design 1

  • Split CreatePanel in home-app.js from a 2-tile grid into a 3-tile grid plus an "Open pattern file" strip. ~80 LOC change, no new files.
  • Tile A (photo) keeps the current image-only file picker (filter image/*) and routes to create.html?action=home-image-pending as today.
  • Tile B (digitise) opens its own picker (filter image/*,.pdf) and sets sessionStorage['cs_pending_wizard_image'] + navigates to create.html?action=open-wizard. creator-main.js grows a new action branch that auto-opens ImportWizard with that image, regardless of the experimental.importWizard flag (the flag is repurposed as a "show wizard as the only image path" advanced toggle).
  • Tile C is unchanged.
  • The bottom strip's "Open pattern file" reuses today's .oxs/.json/.pdf handler in handleFileChange — the only change is splitting it out of the "New" tile so the IA reads as create vs open.
  • The experimental.importWizard preference + per-modal intent screen we shipped on the import branch stay, but become belt-and-braces rather than the primary discovery surface.
Pros
· Flat IA — every intent is one click from the homepage.
· Lowest code risk; reuses existing routing.
· The "Digitise" tile's filter is naturally restrictive (only image+pdf), so users self-select correctly.
· Mobile-friendly (3 tiles stack to a column).
Cons
· The Create tab grows visually busier; needs the "Beta" badge work to flag wizard's experimental status.
· No room to explain when each option is right — copy must do the work.

Implementation proposal — Design 2

  • Replace CreatePanel's tile grid with a 4-button segmented control + a per-mode panel below it. Single new piece of state: const [createMode, setCreateMode] = useState('photo').
  • Each sub-mode renders its own tiles with its own picker filter:
    • Photo → image/*, current Creator route.
    • Printed chart → image/*,.pdf, routes to wizard (as Design 1).
    • Pattern file → .oxs,.xml,.json,.pdf, current ImportEngine route.
    • Blank grid → unchanged.
  • URL state: ?tab=create&sub=chart deep-links to the right sub-mode, so the help drawer / onboarding can link straight to the wizard surface.
  • Each sub-mode's body can include format-specific tips (the dashed callout in the mockup) — answers "is this the right tool?" before the user commits.
  • The legacy experimental.importWizard flag is removed; the wizard becomes the only chart-import path.
Pros
· Strongest user education — each path has room for tips and supporting copy.
· No tile-grid bloat; tab keeps the panel a fixed visual weight.
· Cleanest deep-link story for help / onboarding.
Cons
· Two clicks instead of one to get to the picker (tab → tile).
· Larger UI change; more LOC; needs new icons.

Best results checklist
  • Press the book or magazine as flat as you can — a curved page distorts the grid.
  • Shoot under bright, even light (window or lamp, no flash) so symbols stay sharp.
  • Keep the camera parallel to the page; the wizard can correct mild perspective but not severe tilt.
  • Include the legend in the same shot when possible — saves you mapping symbols by hand later.

Implementation proposal — Design 3

  • New top-level entry point chart-import.html that loads only the scripts the wizard needs: icons.js, user-prefs.js, colour-utils.js, dmc-data.js, creator/import-wizard-bundle.js. Avoids dragging in the full Creator bundle for users who only want to scan a chart.
  • Home / Create tile becomes a single "Digitise a printed chart →" link that navigates to chart-import.html.
  • Wizard's existing 5-step state machine moves into a full-page layout (the steps bar across the top is just the existing wizard chrome lifted out of the modal). On commit, the wizard saves a new project via ProjectStorage.save(), sets it active, and navigates to create.html (or stitch.html) for the user to continue.
  • Add the route to sw.js precache + manifest so it ships as a first-class PWA entry.
  • The legacy modal wizard is removed entirely; the experimental.importWizard preference is retired.
  • Add a tracker on home: when a user opens an image > 2 MP or with a phone-photo aspect ratio via "Create from photo", surface a one-time hint card "Looks like a printed chart? Try the Chart import tool".
Pros
· Maximum discoverability — visible in the global nav.
· Bookmarkable / shareable URL.
· Fastest first paint for the wizard (no Creator overhead).
· Camera capture becomes trivial to add (own page, own permissions prompt).
· Lays groundwork for Phase 2 multi-page PDF UX which needs more vertical real estate than a modal.
Cons
· Largest change: new HTML entry, sw.js precache update, manifest, header nav.
· Splits the import code path between Creator-embedded and standalone — needs a clean interface for the wizard to ship project data back to ProjectStorage.
· Adds a 6th top-level page (already at 5).

Recommendation

Ship Design 1 first — it directly fixes the discoverability problem with the smallest change to home-app.js and routes the wizard via the same handoff plumbing the photo path already uses. Design 2 is the natural Phase 2 once the wizard graduates from experimental, because each pathway needs its own tips/help copy and the segmented control gives it room without bloating the homepage. Design 3 is the right end-state for a multi-page Phase 2 PDF UX and PWA camera capture, but it's a much bigger commitment and shouldn't be done until the wizard's success metrics from Designs 1/2 justify a top-level surface.
