# Cleanup 20: auto-export scheduling out of sync-engine.js (F-012)

Base: `ca971d4ca3e284eb1b6594615f052281ee795475` (`main`, v1.0.211). Prerequisites merged: #362, #363, #364, #365 (cleanup 01–04),
#380 (18), #381 (19). Branch: `claude/sync-scheduler-isolation-4pxppk` (the session's designated branch, used in place of the
requested `cleanup/20-sync-scheduler`; it did not exist on the remote and was created from the verified `main`).

`transitions.md` documents the base sequence before any code moved.

## Finding and boundary

F-012 (sync-engine.js too large, mixed responsibilities) is still current: the engine held the auto-export debounce state
(timer, in-flight flag, queued flag, write-start stamp, two timing constants) inline with the permission probe, the write and
the notifications.

Moved to the classic script `sync-export-scheduler.js` (`SyncExportScheduler.create(run)` returning `{schedule}`): the
decision of **when** `run` is called: coalescing onto a pending timer, the 2000 ms fast delay, the cooldown measured from the
start of the last real write, in-flight exclusion with a single queued follow-up, and settling on success or failure.

Not moved, deliberately:

- `triggerAutoExport` (its `WebDAVSync.changed()` → auto-sync gate → handle lookup order) and `_runAutoExport` (handle read at
  fire time, permission probe, where the write-start stamp is taken, the write, `cs:syncStatusChanged`, `_reportSyncError`
  and the 60 s permission-warning rate limit). Event and toast ownership stays in the engine.
- The folder watcher. Its in-flight guard is raised only after the tick's awaits (so two ticks can overlap while those are
  pending); separating it from the tick body risks changing which ticks overlap. It is pinned by the traces instead, and is a
  candidate for a later PR.
- `webdav-sync.js` scheduling, `ProjectStorage`/`StashBridge` callers, public API.

Interface: `run(markWriteStarted)` returns `undefined` (nothing started) or a Promise that always settles. No injection API:
the scheduler reads the global `Date` and `setTimeout` when used (exactly as the engine did), so tests substitute those.
No new public SyncEngine member (74 members before and after, identical names and types); the only new global is
`SyncExportScheduler`, which a classic script needs in order to be loaded, as with `SyncMergeHelpers` (#380) and
`SyncAttachmentCodec` (#381). It is looked up on first use, like the other helpers.

Timing constants: `FAST_EXPORT_DELAY` 2000, `COOLDOWN_MS` 30000 (moved verbatim), `PERM_WARN_COOLDOWN_MS` 60000 and
`WATCHER_INTERVAL_MS` 10000 (untouched, still in the engine). Operation order is unchanged: the Promise chain is the same
chain returned instead of finished with `.then(settle, settle)` inside the function; the scheduler attaches
`.then(settle, settle)` to that same last Promise, so settling happens at the same microtask depth. `inFlight = true`/`queued
= false` are now set when `run` returns rather than before the chain is built; nothing between those two points can schedule.

## Loading

`<script src="sync-export-scheduler.js">` directly before `sync-engine.js` in `home`, `index`, `create`, `stitch`, `manager`.
Precached in `sw.js`; fingerprints and `BUILD_ID` regenerated by `node build-sw.js`. Jest setup and the two independent vm
harnesses (`tests/support/webdav-device.js`, `tests/syncProtocolSemantics.test.js`) load it. No worker, lazy loader or
bundle includes the engine. No creator, JSX, import-engine or protected-PDF source changed, so no other generator output
changes. Pure cleanup: no help-drawer or changelog entry.

recording folder handle, window, document, Toast and `navigator.locks`; 15 scenarios, recorded from `ca971d4` before any

**Mutation check.** Eight deliberate faults in the scheduler (cooldown 20 s, fast delay 1.5 s, cooldown from completion,
settle only on success, no coalescing, no in-flight blocking, timer cleared late, queued flag not cleared at settle): seven are
caught by the new tests. The eighth is an equivalent mutant: the flag is also cleared when the next run starts, so removing
the clear at settle changes nothing observable.

**Differential.** `node reports/cleanup-20/differential.cjs ca971d4… 3000 60`: 3,000 seeded random sequences of 60 operations

## Limits

- The service-worker lifecycle suite (`tests/service-worker`) could not run: it downloads jszip and PDF.js from cdnjs and the
  sandbox proxy returns 403. Precache listing/fingerprints are covered by `swPrecacheSync`, `syncExportSchedulerLoading` and
  `node build-sw.js --check`; a full offline install/update of the new precache entry is untested here.
- The browser "folder" is OPFS with patched permission answers, not the OS directory picker, a cloud-synced folder, or real
  permission revocation. WebKit/Firefox, physical devices and production CDN/SRI are untested.
- Virtual-clock traces and the differential cover the scheduler's rules and the engine around it; they do not model a real IndexedDB
  or disk and run with fake-indexeddb.
- The watcher, WebDAV scheduling and the engine's remaining size are untouched.
